DeepAgents 接入 Langfuse v4 完整演示

本例记录
  1. handle-order-question：用户完整问题、最终回答、用户编号、会话编号。
  2. 模型调用：模型输入输出、耗时，以及模型实际返回的 token 用量。
  3. query_order 工具：请求参数、返回结果、耗时、异常。

固定版本
  Langfuse 服务端：4.82.0。
  Langfuse Python SDK：5.2.0。
  DeepAgents：0.7.40。
  langchain-openai：1.8.3。
  python-dotenv：1.2.4。
  Python：.python-version 和容器统一使用 3.12；项目最低支持 3.11。
  uv：Docker 固定 0.13.6；本地使用 0.13.6 或更新版本。
  pyproject.toml 声明直接依赖，uv.lock 锁定全部依赖及跨平台安装信息。
  ClickHouse：26.3.62.3；PostgreSQL：17；Redis：7。
  MinIO 跟随 Langfuse 官方 Compose，使用 cgr.dev/chainguard/minio:latest。

运行前准备
  安装 uv，并启动 Docker，确保 uv 和 docker compose 命令可用。
  uv 可管理项目虚拟环境及 Python 版本，无需手动创建或激活 .venv。
  准备支持工具调用的模型 API Key。本例默认使用 gpt-4.1-mini。
  订单查询工具使用内存中的固定数据，无需访问真实订单服务。

最快运行：基础设施和示例都使用容器
  在项目目录执行：
    uv sync --locked
    uv run --locked init_env.py

  打开生成的 .env，在本地填写 OPENAI_API_KEY。
  使用其他兼容 OpenAI 的模型服务时，修改 OPENAI_BASE_URL 和 OPENAI_MODEL。
  模型名称和服务地址应与该服务的接口一致，且模型需支持工具调用。
  默认所有浏览器访问地址都是 localhost，适用于本机演示。

  启动 Langfuse 和所有依赖：
    docker compose up -d --wait --wait-timeout 300

  等待成功后，运行一次 DeepAgent：
    docker compose run --rm --build demo

  普通 docker compose up 不会运行 demo 服务；demo 仅在上条命令显式调用时执行。
  Web 首次启动会自动创建演示组织、项目、API Key 和用户。
  脚本与服务端读取同一份 .env 中的项目密钥。

  浏览器打开 http://localhost:3000。
  登录邮箱见 .env 的 LOGIN_EMAIL；默认 demo@example.com。
  登录密码见 .env 的 LOGIN_PASSWORD。
  进入项目 DeepAgents Order Demo，打开脚本输出的追踪链接。

在页面核对内容
  最外层步骤 handle-order-question 的 Input：
    请调用 query_order 查询订单 ORD-1001，告诉我状态和快递单号。
  最外层步骤的 Output 是模型最终回答。

  找到名称为 query_order、类型为 tool 的步骤。
  Input 应包含：
    {"order_id":"ORD-1001"}
  Output 应包含：
    {
      "order_id":"ORD-1001",
      "found":true,
      "status":"已发货",
      "carrier":"顺丰",
      "tracking_no":"SF-DEMO-1001",
      "items":["无线鼠标"]
    }
  某些视图会把工具返回值包在 ToolMessage 中，展开 content 即可看到上述 JSON。
  通过 v4 Observations API v2 读取时，本例工具 output 为序列化的 ToolMessage；
  先解析外层 JSON，再解析 content 中的 JSON，即可取得 tracking_no 等业务字段。
  工具之前、之后分别有模型调用，记录模型选择工具以及生成最终回答的过程。
  使用 user-demo-001、conversation-demo-001 或 order-demo 标签可以筛选本次追踪。

也可以在宿主机运行 Python
  基础设施仍然通过 Docker Compose 启动，然后执行：
    uv sync --locked
    uv run --locked demo.py
  uv 会按 .python-version 选择 Python 3.12，并管理项目内的 .venv。
  该方式从 .env 读取 LANGFUSE_BASE_URL=http://localhost:3000。
  容器方式会自动改用 http://langfuse-web:3000，浏览器链接仍指向 localhost。

外接已有的自建单机 ClickHouse
  使用 compose.external-clickhouse.yaml，文件中没有本地 ClickHouse 服务及其依赖。
  先在 .env 中修改：
    CLICKHOUSE_URL=http://你的地址:8123
    CLICKHOUSE_MIGRATION_URL=clickhouse://你的地址:9000
    CLICKHOUSE_USER=langfuse
    CLICKHOUSE_PASSWORD=对应密码
    CLICKHOUSE_DB=langfuse
  使用 TLS 时，HTTP 改为 https 和 8443，TCP 改为 9440，
  同时设置 CLICKHOUSE_MIGRATION_SSL=true。
  Docker 容器中的 localhost 指容器自己，应填写容器能访问的数据库地址。

  由数据库管理员创建专用库及用户，可参考 clickhouse-init.sql。
  执行前将 SQL 中的密码占位符改为与 .env 一致。
  该授权 SQL 面向自建单节点；ClickHouse Cloud 应参照官方权限清单单独授权。
  ClickHouse 至少为 25.12，服务器时区必须为 UTC。
  然后执行：
    docker compose -f compose.external-clickhouse.yaml up -d --wait --wait-timeout 300
    docker compose -f compose.external-clickhouse.yaml run --rm --build demo
  外接后 Langfuse 仍使用自己的表；已有业务日志需另行转换导入。

停机和再次运行
  停止服务并保留数据：
    docker compose down
  使用外接版本时，每条管理命令都带 -f compose.external-clickhouse.yaml。
  再次启动与运行沿用同一份 .env。
  SALT、ENCRYPTION_KEY 和数据库密码与已保存数据相关，首次初始化后保留原值。
  init_env.py 遇到已有 .env 会退出并保留原配置。

常见排查
  启动时提示大量变量未设置：先在项目目录运行 uv run --locked init_env.py，
  生成 .env 后再启动 Compose。激活 .venv 只切换 Python 环境，不会生成 .env。
  如果 .env 已存在，先执行 docker compose --env-file .env config --quiet 检查，
  不要删除已有密钥重新初始化。
  终端中已有 LANGFUSE_PUBLIC_KEY 或 LANGFUSE_SECRET_KEY 时，Compose 会优先使用它们。
  如需使用本项目 .env 的密钥，在 up 或 run 命令前加上：
    env -u LANGFUSE_PUBLIC_KEY -u LANGFUSE_SECRET_KEY
  本地 demo.py 以项目 .env 为准，容器中的示例使用 Compose 注入的配置。
  本例直接使用 Docker Hub 上的官方 Langfuse 镜像，版本仍为 4.82.0。
  官方说明同名标签与 docker.langfuse.com 的镜像摘要相同；直接拉取可减少一个网络入口。
  拉取镜像时报 no such host 或 no route to host：检查 Docker Desktop 的网络及代理，
  再执行 docker compose --progress plain pull 查看下载进度。
  --wait-timeout 300 限制的是容器就绪等待，不限制此前的镜像下载时间。
  基础设施未就绪：
    docker compose ps
    docker compose logs --tail=100 langfuse-web langfuse-worker
  认证失败：先等待 Web 健康，再检查 .env 中的密钥是否与当前项目匹配。
  找不到追踪：检查脚本最后是否打印 Trace ID，并确认用户所在项目和时间范围。
  工具没有执行：检查是否使用支持工具调用的模型；脚本会明确报错。
  模型返回 401/404：核对 OPENAI_API_KEY、OPENAI_BASE_URL 和 OPENAI_MODEL。
  端口冲突：修改 Compose 中的宿主机端口，并同步 NEXTAUTH_URL、S3_PUBLIC_URL、
  LANGFUSE_BASE_URL、LANGFUSE_PUBLIC_URL 中对应的端口。

依赖管理
  安装锁定的依赖：uv sync --locked。
  运行初始化脚本：uv run --locked init_env.py。
  运行问答示例：uv run --locked demo.py。
  新增依赖：uv add 包名；移除依赖：uv remove 包名。
  修改已固定的版本时，例如执行 uv add 'langfuse==目标版本'。
  pyproject.toml 与 uv.lock 一起纳入版本控制；.venv 已由 .gitignore 排除。
  Docker 构建同样执行 uv sync --locked，使用同一份锁文件。
  项目声明官方 PyPI 为优先下载源，避免默认镜像尚未同步固定版本。

实现要点
  CallbackHandler 采集 DeepAgents 内部的模型与工具事件。
  外层 start_as_current_observation 显式保存用户问题和最终回答。
  propagate_attributes 将用户、会话和标签传给子步骤。
  finally 中的 flush 确保短脚本退出前发送已缓冲的追踪数据。
  query_order 本身没有再加 observe，避免同一次工具调用重复记录。
